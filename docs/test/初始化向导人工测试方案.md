# 初始化向导（Setup）人工测试方案

## 一、测试目标

验证「首次启动向导」在真实浏览器 + 真实数据库环境下能完成：状态探测、三步表单、邮箱验证码校验、创建首个 ADMIN、写入团队配置、自动登录，并在重复初始化 / 非法输入 / 匿名开关等边界上保持安全与可解释。

## 二、范围与边界

| 覆盖                                                                         | 不覆盖                                     |
| -------------------------------------------------------------------------- | --------------------------------------- |
| `GET /api/setup/status`、`POST /api/setup/init`、`POST /api/auth/email-code` | SMTP 真实投递（需 `MAIL_ENABLED=true`，另见 4.4） |
| `/setup` 页三步流程与全部前端校验                                                      | 注册 / 登录 / 找回密码的完整回归（仅做必要冒烟）             |
| 初始化后的 JWT 自动登录与 ADMIN 权限                                                   | 导入、问答、审核等业务功能                           |
| `kb_user` / `app_setting` / `kb_email_code` 落库结果                           | 多实例并发部署、性能压测                            |
| 「匿名访问问答」开关对 `/api/qa/**`、`/api/kb/**` 的影响                                  | 前端路由级权限（已由单测/回归覆盖）                      |

## 三、被测对象

| 类型    | 位置                                                                                           |
| ----- | -------------------------------------------------------------------------------------------- |
| 控制器   | `src/main/java/com/guangqian/springkb/controller/SetupController.java`                       |
| 服务    | `service/SetupService.java`、`service/AppSettingService.java`、`service/EmailCodeService.java` |
| 页面    | `frontend/src/views/Setup.vue`（路由 `/setup`，`meta.public`）                                    |
| 鉴权    | `config/SecurityConfig.java`（`/api/setup/**` permitAll；`/api/qa/**`、`/api/kb/**` 受匿名开关控制）    |
| 数据表   | `kb_user`、`app_setting`、`kb_email_code`                                                      |
| 已有自动化 | `src/test/java/com/guangqian/springkb/setup/SetupApiTest.java`（2 个用例）                        |

**约定**：所有接口 HTTP 状态恒为 200，业务结果看 `code`（`0` 成功，非 0 失败，`message` 为提示语）。

## 四、环境准备

### 4.1 启动服务

```powershell
# 后端（默认 spring.profiles.active=dev，连 docker-compose 的 pgvector）
.\mvnw.cmd spring-boot:run

# 前端
cd frontend; npm run dev
```

- 后端：`http://localhost:8080`；前端：`http://localhost:5173`
- dev profile 下 `app.auth.code-echo` 默认 `true`，发送验证码的响应会带 `devCode`，页面也会显示「开发环境验证码：xxxxxx」，**无需 SMTP 即可跑通**。

### 4.2 数据库连接

| 项           | 值                                |
| ----------- | -------------------------------- |
| 地址          | `localhost:63892`                |
| 库 / 用户 / 密码 | `ragdb` / `postgres` / `ragpass` |

```powershell
$env:PGPASSWORD='ragpass'
psql -h localhost -p 5432 -U postgres -d ragdb
```

### 4.3 每轮用例前的重置脚本

```sql
DELETE FROM kb_email_code;
DELETE FROM kb_user;
DELETE FROM app_setting WHERE key IN ('team_name', 'allow_anonymous', 'setup_complete');
```

> 注意：`AppSettingService.allowAnonymous` 是启动时加载的 `volatile` 内存值，**SQL 直接删除配置不会刷新缓存**。若上一轮把匿名开关关掉过，重置后必须**重启后端**，否则 `/api/qa/**` 仍会要求登录。

### 4.4 验证码获取（两种模式）

| 模式         | 配置                                                                                                 | 获取方式                              |
| ---------- | -------------------------------------------------------------------------------------------------- | --------------------------------- |
| 回显（推荐人工测试） | 默认 dev                                                                                             | 页面「开发环境验证码」提示，或响应体 `data.devCode` |
| 真实发信       | `MAIL_ENABLED=true` + `MAIL_HOST` + `MAIL_USERNAME` + `MAIL_PASSWORD`，且 `APP_AUTH_CODE_ECHO=false` | 查收邮箱；接口不再返回 `devCode`             |

### 4.5 建议测试数据

| 字段     | 值                   |
| ------ | ------------------- |
| 团队名称   | `平台架构组`             |
| 管理员用户名 | `admin`             |
| 管理员邮箱  | `admin@test.local`  |
| 密码     | `Passw0rd!`（至少 6 位） |

## 五、用例清单

### A. 状态探测与入口

| 编号        | 前置           | 步骤                      | 预期                                                                    |
| --------- | ------------ | ----------------------- | --------------------------------------------------------------------- |
| SETUP-A01 | 已按 4.3 重置并重启 | 浏览器直开 `/setup`          | 短暂显示「正在检查初始化状态…」后进入步骤 1「团队信息」；控制台无报错                                  |
| SETUP-A02 | 同上           | `GET /api/setup/status` | `code=0`，`data.initialized=false`，`userCount=0`，`allowAnonymous=true` |
| SETUP-A03 | 已完成一次初始化     | 未登录访问 `/setup`          | 显示「系统已完成初始化 / 无需重复初始化」，只有一个「去登录」按钮，不出现任何表单                            |
| SETUP-A04 | 已完成初始化且已登录   | 访问 `/setup`             | 自动 `router.replace('/')` 回首页                                          |
| SETUP-A05 | 后端未启动        | 访问 `/setup`             | 显示「暂时无法初始化 / 无法连接后端服务…」+「重试」；启动后点重试可恢复                                |
| SETUP-A06 | 任意           | 访问 `/login`             | 页面无「初始化」入口（当前需手动输入 `/setup`，见缺口 G2）                                   |

### B. 表单校验（步骤 1 / 步骤 2）

| 编号        | 步骤                         | 预期                                                                    |
| --------- | -------------------------- | --------------------------------------------------------------------- |
| SETUP-B01 | 步骤 1 团队名称留空，点「下一步」         | 停在步骤 1，提示「请输入团队名称」                                                    |
| SETUP-B02 | 团队名称填 41 个字符               | 输入框 `maxlength=40` 截断到 40 位；后端无长度校验，绕过前端直接调接口会按原样（`trim` 后）入库（记录为观察项） |
| SETUP-B03 | 团队名称填  `  平台架构组  `  后完成初始化 | 落库 `team_name` 为 `平台架构组`（后端 `trim`）                                   |
| SETUP-B04 | 用户名填 2 位（如 `ab`）           | 提示「用户名长度需在 3-32 个字符之间」，不进入步骤 3                                        |
| SETUP-B05 | 用户名填 33 位                  | 同上长度提示                                                                |
| SETUP-B06 | 邮箱填 `admin`（无 @）           | 提示「邮箱格式不正确」                                                           |
| SETUP-B07 | 邮箱留空点「发送验证码」               | 先触发「请输入管理员邮箱」，不发请求                                                    |
| SETUP-B08 | 邮箱合法，点「发送验证码」              | 按钮变为「60s 后重发」并逐秒倒计时；页面出现开发环境验证码；提示「验证码已生成」                            |
| SETUP-B09 | 冷却期内刷新页面再点「发送验证码」          | 本次可再次点击（前端计时器丢失），后端返回 `code=400`「验证码已发送，请 60 秒后重试」                    |
| SETUP-B10 | 验证码填 5 位或含字母               | 提示「验证码为 6 位数字」                                                        |
| SETUP-B11 | 密码填 5 位                    | 提示「密码长度至少 6 位」                                                        |
| SETUP-B12 | 确认密码与密码不一致                 | 提示「两次输入的密码不一致」                                                        |
| SETUP-B13 | 步骤 2 点「上一步」再点「下一步」         | 已填内容不丢失，校验重新执行                                                        |
| SETUP-B14 | 全部合法后进入步骤 3                | 汇总区正确显示团队名称、`用户名（邮箱）`、匿名问答「允许/不允许」                                    |

### C. 正常主流程

| 编号        | 前置                    | 步骤                      | 预期                                                                            |
| --------- | --------------------- | ----------------------- | ----------------------------------------------------------------------------- |
| SETUP-C01 | 未初始化                  | 按 4.5 数据完成三步并点「完成初始化」   | 按钮变「初始化中…」且禁用；成功后提示「初始化完成，已自动登录」并跳转 `/`                                       |
| SETUP-C02 | 接 C01                 | 观察导航栏                   | 显示已登录用户与「管理后台」入口（JWT 已写入，无需再登录）                                               |
| SETUP-C03 | 接 C01                 | 访问 `/admin`             | 可正常进入管理后台概览（ADMIN 角色生效）                                                       |
| SETUP-C04 | 接 C01                 | `GET /api/setup/status` | `initialized=true`，`userCount=1`，`teamName=平台架构组`，`allowAnonymous` 与步骤 1 选择一致 |

### D. 重复初始化与越权

| 编号        | 前置                             | 步骤                                               | 预期                                            |
| --------- | ------------------------------ | ------------------------------------------------ | --------------------------------------------- |
| SETUP-D01 | 已初始化                           | `POST /api/setup/init` 重放同一请求体                   | `code=400`「系统已初始化，禁止重复执行」；`kb_user` 仍只有 1 条   |
| SETUP-D02 | 已初始化                           | 重启后端后再次 `POST /api/setup/init`                   | 仍为 400（判断依据是用户数，不依赖 `setup_complete`）         |
| SETUP-D03 | 已存在任意 MEMBER（手工插入一条 `kb_user`） | `GET /api/setup/status` 与 `POST /api/setup/init` | `initialized=true`、`userCount>=1`；init 返回 400 |
| SETUP-D04 | 匿名（无 token）                    | 调 `GET /api/admin/documents`                     | 401，不泄露任何数据                                   |
| SETUP-D05 | 非管理员 token                     | 调 `GET /api/admin/documents`                     | 403「无权限访问（需要管理员角色）」                           |

### E. 边界与异常

| 编号        | 步骤                                        | 预期                                                         |
| --------- | ----------------------------------------- | ---------------------------------------------------------- |
| SETUP-E01 | `POST /api/setup/init` 空 body             | `code=400`「请求体不能为空」                                        |
| SETUP-E02 | 用户名 `admin`、密码 `123456`、验证码错误（如 `000000`） | `code=400`「验证码不存在或已过期」或「验证码错误」；不创建用户                       |
| SETUP-E03 | 使用 `login` 用途的验证码提交初始化                    | 失败（后端固定按 `register` 用途校验）；用 `register` 码才成功                |
| SETUP-E04 | 同一验证码连续提交两次（第一次成功建号，第二条在重置库后）             | 首次成功即 `used=true`；重置库前重复使用返回「不存在或已过期」                      |
| SETUP-E05 | 发码后等待超过 5 分钟再提交                           | `code=400`「验证码不存在或已过期」                                     |
| SETUP-E06 | 初始化请求中省略 `allowAnonymous`                 | 默认按 `true` 落库（`allow_anonymous=true`）                      |
| SETUP-E07 | 初始化请求中 `teamName` 为空串或全空格                 | 落库 `team_name` 为「我的团队」                                     |
| SETUP-E08 | 用户名前后带空格（如 `admin`，绕过前端 trim）             | 后端不 trim，按原样入库；登录需用带空格的用户名（记录为观察项，见 G4）                    |
| SETUP-E09 | 邮箱大小写混写（`Admin@Test.Local`）               | 归一化为小写入库；`kb_email_code.email` 同样为小写                       |
| SETUP-E10 | 并发两个 `POST /api/setup/init`（同一邮箱码）        | 至多一个成功；另一个返回 400 或 500（唯一索引兜底），`kb_user` 不出现两个 ADMIN（见 G5） |
| SETUP-E11 | 密码含中文 / 空格 / 特殊字符                         | 正常创建，BCrypt 可校验，登出后可用该密码登录                                 |

### G. 数据一致性（psql 断言）

| 编号        | 断言                                                                         | 预期                                                       |
| --------- | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| SETUP-G01 | `SELECT username, email, role FROM kb_user;`                               | 1 条，`role='ADMIN'`，`email` 为小写                           |
| SETUP-G02 | `SELECT length(password_hash), left(password_hash, 4) FROM kb_user;`       | 长度 60，前缀 `$2a$` 或 `$2b$`（BCrypt，非明文）                     |

| SETUP-G04 | `SELECT email, purpose, used, expires_at > created_at FROM kb_email_code;` | 本次验证码 `purpose='register'`、`used=true`、5 分钟有效期           |

## 六、已知缺口与建议

> 状态（2026-11-06）：G1\~G5 已修复（commit `bfb9ac3`），G6 仍未处理。修复后断言变化：B03/B05/E08 后端统一 `trim` + `^[A-Za-z0-9_-]{3,32}$`，含中文或中间空格一律 400；B02 仍成立（40 字上限仅在系统设置页，Setup 接口只做 `trim`）；G03 中 `setup_complete` 由原子占位写入。

| 编号 | 现象 | 影响 | 建议 |
| --- | --- | --- | --- |
| G1 | `team_name` 只写不读：全站无页面展示团队名（仅 `setup/status` 返回） | 步骤 1 的输入对用户无可见反馈 | 在 `NavBar` 或首页标题展示团队名 |
| G2 | 未初始化时无自动跳转：`/login` 无「去初始化」入口，只能手输 `/setup` | 首次部署易卡在登录页 | 登录页根据 `setup/status.initialized=false` 显示引导按钮 |
| G3 | `allow_anonymous` 无运行期修改入口 | 想改只能改库或重跑初始化 | 管理后台「系统设置」增加开关（复用 `AppSettingService.setAllowAnonymous`） |
| G4 | 用户名后端不 `trim`、不校验字符集 | 前后端不一致，可能产生带空格账号 | 后端统一 `trim` 并限制 `[A-Za-z0-9_-]` |
| G5 | 初始化仅靠「用户数 == 0」判断，无数据库级互斥 | 并发首启可能一个请求 500 | 唯一索引已兜底；可用 `INSERT ... ON CONFLICT DO NOTHING` + 影响行数判断 |
| G6 | `SetupService.init` 先消费验证码再插入用户 | 插入失败时验证码已作废，需等 60s 重新发码 | 改为「校验 → 插入 → 消费」 |

## 八、通过标准

1. A/C/D/G 组用例 **100% 通过**（核心链路与数据一致性）。
2. B/E/H 组用例通过率 ≥ 90%，未通过项须有明确缺陷记录，且不得为「可绕过校验创建非 ADMIN 账号」「已初始化后仍能创建管理员」这类安全问题。
3. F 组中 F01、F02、F03 必须通过（匿名开关即时生效且持久化）；F04 属已知缺口，不计入阻塞。
4. 全程无后端 500、无前端控制台报错、无明文密码入库。
