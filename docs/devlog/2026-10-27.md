## 三、监控脚本重写

`scripts/monitor-crawl.ps1` 原实现问题：

1. 日志被爬虫进程独占，`Get-Content` 直接报「文件正由另一进程使用」；
2. 日志由 PowerShell 重定向写入，**中文在写入侧已被破坏**，脚本剔非 ASCII 后靠猜字段，进度经常为空；
3. 正则只取每行第一个 `[tag]`，而 `[ main]` 排在 `[elasticsearch]` 前，导致候选数全丢。

重写要点：

- 进度改为读 **`.crawl-state.json`（done/docs）+ `.partial/*.urls`（已抓行数）**，日志只提供 PID / 时间戳 / 候选数；
- 日志读取用 `FileStream` + `FileShare.ReadWrite`，并按换行边界裁剪尾部字节；
- 遍历行内所有 `[tag]`，只认注册过的数据源名；
- 表格列：数据源 / 状态 / 进度 / 候选 / 落盘KB / 速率，排序为抓取中 → 等待 → 完成；
- 汇总：完成源数、已登记篇数、抓取中、等待、失败请求去重 URL、最近日志。

## 七、经验教训

1. **链路层面的 reset 只能靠重试次数解决**：改 UA / 改连接头无效时，先量化「单次成功率」，再按 `1-(1-p)^n` 选重试次数；同时把重试做成站点级可配置，不要全局调高（会拖慢其它源）。
2. **进度与状态必须落盘，不能只依赖日志输出**：日志会被重定向破坏编码、也会被进程独占；状态文件 + 增量文件才是可靠事实源。
3. **「进程在」不等于「任务在跑」**：判断爬虫是否结束要看断点文件是否增长、日志时间戳与 CPU 增量。
4. **幂等跳过是正常现象，不是失败**：重跑全量导入时旧源 100% 跳过（1512 篇），看 `skipped` 要区分「已存在」与「空正文」。
5. **chunk 大小要按语言估算 token**：`字符数/4` 只适用于英文；中文语料应按「CJK 字符 ≈ 1 token」估算，否则会撞 Embedding 输入上限。

## 九、CJK token 估算与超长块兜底修复（当日追加）

**问题**：mysql `mysqlbinlog` / `gpg-key-archived-packages` 导入报 `Tokens in a single document exceeds the maximum number of allowed input tokens`。Spring AI 的 `TokenCountBatchingStrategy` 用 CL100K 统计，上限 8191、预留 10%（约 **7371**），单条 Document 超限即抛异常。

**根因（两处叠加）**：

1. `TokenEstimator.estimate` 统一按 `字符数/4`：中文约 1 字 ≈ 1 token，被低估约 4 倍；
2. `hardSplit` 对代码围栏内的行不做预算检查，一个 2.6 万字符的代码块会整体落成一个 chunk（估 6660 token，CL100K 实测已超 7371）。

**修复**：

| 位置 | 改动 |
| --- | --- |
| `TokenEstimator` | 按字符权重累加：CJK（汉字/假名/谚文/全角）1 token/字符，其余 4 字符/token；新增未取整的 `weightSum` 供逐行预算使用 |
| `ChunkSplitter.hardSplit` | 逐行用 `weightSum + 换行权重` 计预算（避免大量短代码行因逐行取整而系统性低估约 25%）；围栏块上限 **2×maxTokens**，超限时「补闭合围栏 → 以同语言标记重开」，每块围栏仍成对 |
| `ChunkSplitter.splitLongLine` | 超长单行改为按 token 预算切分（原按 `maxTokens*4` 字符切，中文会切不动） |
| `ChunkSplitter.pack` | 增加单块硬上限 2×maxTokens 的 flush 条件 |

**验证**：

- 实测两篇失败文档（用 CL100K 直接数 token）：`mysqlbinlog` 10 chunk / maxEst 1987 / **maxReal 1932**；`gpg-key-archived-packages` 8 chunk / maxEst 1993 / **maxReal 5761**，全部 < 7371；
- 重导 `--import=mysql`：2346 篇 → **ok=2 / skip=2344 / fail=0**（耗时 8s），两篇均已入库，`kb_chunk` 与 `vector_store` 各 10 / 8 条对齐，`token_count` max 1987 / 1993；
