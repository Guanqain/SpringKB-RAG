## P1 Spring 官方文档元数据错乱（version=web/servlet/repositories）

- **现象**：小样本冒烟后 `data/raw/springframework.json` 出现 `version="web"`、`docKey="webflux-cors"`；`springsecurity` 出现 `version="servlet"`；`springdatajpa` 出现 `version="repositories"`。若直接导入，会把同一篇文档算成新文档（导入 id = `{product}-{version}-{docKey}`）。
- **根因**：`docs.spring.io` 的 sitemap 同时收录两类 URL：
  - 版本化历史页：`/7.1-SNAPSHOT/core/aop-api/advice.html`、`/6.2/...`
  - 不带版本的当前页：`/web/webflux-cors.html`、`/servlet/...`
  原实现把路径首段无条件当版本号，并且「取最大版本」按字符串比较，`web`/`servlet` 这类单词字典序大于数字版本，导致整批元数据被带偏。
- **解决方案**（`AbstractSpringReferenceCrawler`）：
  1. 版本目录必须匹配 `^\d+(\.\d+)*(-[A-Za-z0-9.]+)?$`，否则不算文档页；
  2. `collectUrls()` 只保留版本化页面，并取版本号最大的一版（避免同文多版本稀释检索）；
  3. 标题清理 Antora 后缀（` :: Spring Framework`）；
  4. 单测 `DocsCrawlerMappingTest` 锁定 `version/docKey/docType/section` 映射。
- **经验教训**：解析站点 sitemap 前必须先打印几条样本确认 URL 形态；「字符串取最大」不能代替版本语义比较。导入 id 含 version，元数据错会直接产生重复文档。

## P2 `ApplicationArguments.getOptionValue` 编译失败

- **现象**：`CrawlerRunner.java:[65,26] 找不到符号 getOptionValue`。
- **根因**：Spring Boot 4 的 `ApplicationArguments` 只保留 `getOptionValues(String)`。
- **解决方案**：改为 `getOptionValues("crawl-limit")` 取列表首元素，空值/非法值回落 `DEFAULT_LIMIT = 80`。
- **经验教训**：升级大版本后，命令行参数读取 API 需按新签名重查，不要沿用旧代码片段。

---

## P3 `--import=all` 无法覆盖新增源

- **现象**：新增 7 个爬虫源后，`--import=all` 仍只导入旧的 3 个源。
- **根因**：`ImportRunner` 内部维护硬编码 `ALL_SOURCES` 白名单。
- **解决方案**：`all` 时扫描 `data/raw/*.json`，文件名即 source；显式 `--import=a,b` 仍按参数执行。新增源无需改代码。
- **经验教训**：数据源清单属于**目录事实**，应由文件系统发现，避免代码内白名单与爬虫源脱节。
