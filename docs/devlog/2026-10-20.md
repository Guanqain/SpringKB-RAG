## P1 集成测试向量写入 IndexOutOfBoundsException

- **遇到时间**：约 01:00
- **现象**：`IngestionServiceTest` 导入文档时，`vectorStore.add()` 内部抛 `IndexOutOfBoundsException`（`embeddings.get(documentIndex)`），且错误行号指向 PgVectorStore 的批量嵌入逻辑。
- **根因**：`EmbeddingModel` 被 `@MockitoBean` 替换后，接口的 **default 方法**（`embed(List<Document>, EmbeddingOptions, BatchingStrategy)`）在 mock 下返回空集合；PgVectorStore 调它拿到空列表后再按下标取向量，直接越界。仅 stub 非 default 的 `call(EmbeddingRequest)` 不够。
- **解决方案**：
  1. 显式 stub default 方法，按文本 hashCode 生成确定性 1024 维向量（±0.5，避免全零）；
  2. 同时 stub `call(EmbeddingRequest)` 作双保险；
  3. 用 `@MockitoBean FakeDocumentSeeder` 挡住 demo seeder 在空测试库首启时触发未 stub 的 embedding。
- **经验教训**：Spring 集成测试中 mock 有 default 方法的接口，必须确认被测框架实际调用的是哪个方法；Spring AI 的 `EmbeddingModel.embed(List, ...)` 是 default，必须显式 stub。

## P3 Matcher.replaceAll(Function) 对 `$`/`\` 二次解释导致真实文档导入失败

- **遇到时间**：约 02:00
- **现象**：`--import=all` 导入 vue 真实文档时，含 `$refs`/`$store`/`$emit` 的章节抛 `IllegalArgumentException: Illegal group reference`（部分场景报 `named capturing group has 0 length name`），`/api/*` 等 vue 文档全部导入失败。
- **根因**：`ChunkSplitter.toText` 中 `IMAGE_PATTERN/LINK_PATTERN/INLINE_CODE_PATTERN` 的 `matcher.replaceAll(m -> ...)` 在 JDK 内部走 `appendReplacement`，会把**返回字符串**中的 `$` 与 `\` 当替换组引用解析。真实 Vue 文档大量包含 `$` 标识符（`$refs`/`$emit`/`$store`），直接触发解析异常。
- **解决方案**：三个 replaceAll 的 lambda 返回统一包 `Matcher.quoteReplacement(...)`：
  ```java
  t = IMAGE_PATTERN.matcher(t).replaceAll(m -> Matcher.quoteReplacement("[图片] " + m.group(1)));
  t = LINK_PATTERN.matcher(t).replaceAll(m -> Matcher.quoteReplacement(m.group(1)));
  t = INLINE_CODE_PATTERN.matcher(t).replaceAll(m -> Matcher.quoteReplacement(m.group(1)));
  ```
- **回归测试**：`ChunkSplitterTest` 新增 #8（`cleansContentWithDollarSignsAndBackslashes`）：构造含 `$refs`/`$el`/`$store.state`/`$emit`、`\frac{1}{2}`、行内代码 `` `C:\temp\file` ``、链接 `[Windows path docs](...)` 的 markdown，断言 split 不抛异常、`$` 原样保留、链接语法剥离、反斜杠不转义。
- **经验教训**：凡 `replaceAll(Function)` 返回值来自用户/文档内容时，必须 `quoteReplacement` 转义；这也是**集成测试用真实/近似真实数据才能暴露**的一类问题。

## P5 百炼 text-embedding-v4 批量上限（单请求输入 ≤ 10 条）

- **遇到时间**：约 02:50
- **现象**：`testing/spring-boot-applications`（31 chunks 超大文档）导入失败，vectorStore.add 抛百炼 `400: ... batch size ... larger than 10`（更早批量 25 时报 "larger than 20"，说明上限随请求体变化）。
- **根因**：`IngestionService.importDocument` 一次 `vectorStore.add(全部 aiDocs)` 提交所有 chunk，超过百炼单请求输入上限。
- **解决方案**：`EMBEDDING_BATCH_SIZE = 8`（留余量），`for` 分批提交：
  ```java
  for (int i = 0; i < aiDocs.size(); i += EMBEDDING_BATCH_SIZE) {
      vectorStore.add(aiDocs.subList(i, Math.min(aiDocs.size(), i + EMBEDDING_BATCH_SIZE)));
  }
  ```
- **回归测试**：新增 `IngestionBatchTest`（`@MockitoBean VectorStore`，只记录 add 调用）：构造 25 章节 × ~1000 token → >20 chunks，断言 `atLeast(2)` 次 add、每批 ≤ 8、批内总数 == splitter 产出数。
- **经验教训**：真实 Embedding API 有批量上限，超大文档必须分批；分批大小留 20% 余量防模型侧调整。`RawDocument` 构造参数是 15 个（contentText 在 contentMarkdown 前）；测试用 UUID docKey 避免幂等命中导致 add 零调用。

### Task 6 前端 Bug 修复（联调复验发现）：状态开关提示文案反向

- **现象**：文档列表页点击状态开关，将其"启用"时提示"已停用"，将其"停用"时提示"已启用"，操作方向与提示相反。
- **根因**：`DocumentList.vue#onToggleActive` 用 `ElMessage.success(\`${doc.active ? '已启用' : '已停用'}\`)`生成提示，但`doc.active` 是**切换前**的旧值（请求尚未完成、列表行未替换），旧值取反方向正好与本次操作相反。
- **解决方案**：提示前先取 `const target = !doc.active`（本次切换的目标状态），文案按 `target` 判断：
  ```ts
  const target = !doc.active
  await store.toggleActive(doc)
  ElMessage.success(`${target ? '已启用' : '已停用'}：${doc.title}`)
  ```
- **验证**：`npm run build`（vue-tsc + vite）通过；浏览器实测两个方向均与操作一致（OFF→ON 提示"已启用"、ON→OFF 提示"已停用"）。
- **经验教训**：异步切换类 UI 的反馈文案必须基于**目标值/服务端返回值**计算，禁止读取操作前的旧状态；同时注意 `store.toggleActive` 替换列表行后，闭包里的 `doc` 仍是旧对象引用。

### 过程问题（2 个，均为**自动化验证误报**）

1. **角标脉冲被误判为失效（坑 #23 的再现）**：两轮浏览器 agent 均报「未检测到 `hl` 类 / animationName=none」。经 Mutation 级波动轮询复核：点击后 55ms 即出现 `.gb.hl`，`animationName = qa-pulse-<hash>`（Vue scoped 会给 keyframes 加 hash），1.3s 后移除 → **功能正常，误报源于检测方法**（只看动画结束态 / 以 `qa-pulse` 字面名匹配 / DevTools 自身 highlighting 的干扰）。**教训**：必须按 #23 的规则在动画窗口内轮询，且动画名要按前缀 `qa-pulse` 匹配而非全等。
2. **「未登录重定向」被误判为失效**：首轮 agent 未清 localStorage，浏览器残留上一会话 JWT → 守卫按「已登录」放行 `/`，被读成「守卫失效」。清 `localStorage` 后重测为 ✅。**教训**：登录态相关的回归项必须先 `localStorage.clear()` 重置到未登录态再测。

## 视觉基调 v2.1 ·「档案馆 / 书房」（2026-10-20 晚）

**设计基线**：[docs/用户端前端设计.md](../用户端前端设计.md) v2.1（§3.1 token / §6.1 问答页对话流 / §6.2 管理端控制台 / §6.3 外壳 / §10 空态 / §11 验收）

### 背景与决策

v2.0 的「暖橘 SaaS」视觉与产品定位（**私有化单实例团队知识库**）不匹配：渐变主按钮、Hero 光斑、网格背景、卡片彩色投影更像营销落地页，而不是「在书房查资料」。本轮**废止暖橘渐变视觉**，改为**档案馆 / 书房**基调，并按用户要求**先改文档、再改代码**。

三条硬约束：① 分层只用 `1px` hairline，卡片/列表**零阴影**（阴影仅浮层）；② 主操作 = 深墨实底 `#1C1917`，**零渐变**；③ 品牌强调 = 沉陶土 `#B45309`，**极小面积**（导航活跃点 / 链接 hover / focus ring / 信号点），高饱和亮橘 `--brand-400` 只在「引用脉冲」这一单点高光出现。

### 实现（前端）

- **设计基座**：`styles/theme.css` 整体重写 —— 新增 `--page-bg #F7F5F0` / `--surface` / `--surface-sunken` / `--admin-bg #F5F5F4` / `--hairline #E7E2D8` / `--hairline-strong`、暖灰 ink 阶（`--ink-900` = 深墨）、沉陶土 brand 阶；**删除** `--grad-brand`/`--grad-soft`/`--grad-hero`/`--glow-brand` 与 `--shadow-xs..xl`；阴影只留 `--shadow-overlay-sm`/`--shadow-overlay`；`body{line-height:1.7}`；新增 `.num`（`--font-num` + `tabular-nums`）；Element Plus 覆盖改墨色主色 + hairline 边框 + 表格行 hover `#F5F5F4`，输入类 focus 改 `box-shadow: var(--ring)`（1px 陶土）。
- **问答页对话流（核心）**：由「居中一张大卡片」重排为**对话流** —— 阅读栏 `--measure 760px`；用户问题靠右浅色气泡（`--ink-100`）；答案靠左无气泡直接排在纸面上；`[n]` 极小上标（11px / `vertical-align: super`）点击滚动到来源卡并触发**一次**陶土脉冲；来源卡横向排列（徽标 + 标题 + 摘要 + 「打开原文」禁用态）；输入区 `sticky bottom:0` 固定底部，深墨实底发送按钮，Enter 发送 / Shift+Enter 换行；加载为**三行灰条 + 一个脉冲点**（移除转圈）；空态「问点什么，或者从下面挑一个」+ 3 示例 chip。
- **管理端控制台**：`220px` 深墨侧边栏（active = 左 3px 陶土描边 + 极淡陶土底）；主区 `--admin-bg` + 顶部 46px hairline 工具条；4 统计卡大号 `tabular-nums` 数字 + hairline 分隔；表格去竖线/去斑马纹/行 hover `#F5F5F4`；表格与抽屉空态改「一句话 + 动作按钮」。
- **外壳与其余页**：NavBar 去渐变方标（深墨方标）/ 去阴影；AppFooter 链接色改中性；`Home` 删除 Hero 光斑、网格背景与逐张入场动画；`Login` 登录按钮改深墨实底；`Kb/KbDoc/Setup/Me/Editor` 及 4 个 admin 占位页空态统一为「有态度的一句话 + 一个动作按钮」，**全站清除「功能开发中」字样**。

### 记录待裁决：注册即管理员（C1 / C3）

实测 `AuthService.DEFAULT_ROLE = "ADMIN"`，**任意人注册即成为管理员**；`SecurityConfig` 对 `/api/admin/**` 只校验登录、不校验角色。已按用户要求**记录并给出建议方案**（写入 `docs/用户端前端设计.md` §9.1）：**首个注册者 = 主管理员（bootstrap）→ 之后注册一律 MEMBER → 角色变更仅由 ADMIN 通过 `PATCH /api/admin/users/{id}/role` 发起 → `/api/admin/**` 收敛为 `hasRole('ADMIN')`**。

**本轮不改后端的理由**：单独把注册默认角色改为 `MEMBER` 而鉴权未同步收紧，会产生「普通成员照样能进管理后台」的**假安全**；角色写入、鉴权与成员管理必须**同批发布**，故本轮只落地前端徽标归一化。

### 审查结论（健壮性 / 可行性 / 安全性）

- **健壮性**：角标替换用正则**带捕获组的 `split`** 先切出 `<pre>`/`<code>` 段并原样跳过，避免代码示例里的 `[n]` 被误替换；角标 HTML 只由数字常量拼接且**注入在 DOMPurify 净化之后**，不引入新的注入面；越界编号（不在 `1..totalSources`）保持纯文本不生成角标。`[n]` 点击改事件委托，规避 `v-html` 无法绑定事件的问题。
