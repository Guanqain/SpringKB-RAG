## P1 问答不回显 + 前端超时

- **现象**：
  1. 前端 `/qa` 输入问题，加载骨架一直转，30s 后报超时错误；
  2. 后端控制台日志看起来「处理完成」，但没有响应回前端；
  3. 断点停在该行：`return ApiResponse.ok(qaService.ask(...))`（[QaController.java#L76](../src/main/java/com/guangqian/springkb/controller/QaController.java)），像是「return 卡住」。
- **排查证据**：
  1. `jcmd <pid> Thread.print` 连续两次（间隔 12s）线程栈完全一致：`http-nio-8080-exec-1` 停在 `QaService.ask`，CPU 不再增长 → 不是死循环，是外部调用阻塞；
  2. 其余请求线程停在 `SubscriberInputStream.read` / `ReactorClientHttpRequest.executeInternal`，全部在等出站 HTTP 响应；
  3. 后端日志出现 `HttpClientConnect: [.. ! R:api.deepseek.com/123.182.162.200:443] The connection observed an error` + `Connection closed while SSL/TLS handshake was in progress`；
  4. 同网络下 `api.deepseek.com:443` TCP 连接失败，`dashscope.aliyuncs.com` 同样不可达；**换网络后恢复正常**。
- **根因**：
  - 直接原因：模型服务出站连接不可用，握手阶段被断。
  - 放大因素：Spring AI 的 `RestClient` 未配置连接/读取超时，Netty 客户端会一直等，Tomcat 请求线程被长期占用；前端 [http.ts](../frontend/src/api/http.ts) 全局 `timeout: 30000` 先到期，于是「前端超时 + 后端稍后才失败/一直挂着」。
  - 注意：这不是「检索链路故障」，也不是 `return` 语句本身的问题——`return` 行的表达式里包含着整段模型调用。
- **解决方案**：
  1. `application.yml` 增加出站超时与重试收敛：

     ```yaml
     spring:
       http:
         client:
           connect-timeout: 5s
           read-timeout: 60s
       ai:
         retry:
           max-attempts: 1   # 不自动重试，最坏 ≈65s，落在前端 90s 内
     ```
  2. `QaService#generate` 捕获模型调用的运行时异常，转换为 `ModelUnavailableException`（新增领域异常），日志保留原始堆栈；
  3. `QaController#ask` 捕获该异常返回 `code=503 / "模型服务暂时不可用，请稍后重试"`，与「知识库未收录」的 `found=false` 明确区分；
  4. 前端 `api/qa.ts` 给 `/qa/ask` 单独设 `timeout: 90000`，其余接口仍用全局 30s；
  5. 新增单测 `QaServiceTest#modelFailureMapsTo503`：`content()` 抛异常 → service 抛 `ModelUnavailableException`、控制器返回 503。
- **验证**：
  - `mvn test`：`Tests run: 55, Failures: 0, Errors: 0`
  - `npm run check`（vue-tsc）：通过
  - 换网络后 `/api/qa/ask` 正常返回答案与引用
- **经验教训**：
  1. 「控制层 return 卡住」要先怀疑 **return 表达式里的调用**，不要顺着「序列化/响应写出」的方向查；线程转储是区分「死循环」与「阻塞在外部 IO」最快的手段。
  2. 任何外部 HTTP 依赖都必须配 **连接超时 + 读取超时 + 有限重试**，否则网络抖动的代价是线程池被耗尽而不是一次失败。
  3. 前端超时必须 ≥ 后端最坏耗时（连接 5s + 读取 60s ≈ 65s < 90s），否则用户永远只能看到超时而不是友好错误。
  4. 「知识库没有答案」与「模型挂了」是两种语义，状态码/提示语必须分开，否则会误导排查方向（也会污染产品指标）。
