# SpringKB 前端界面设计 v2

**版本**：v2.0（2026-10-20）
**取代**：v1.1（2026-10-20，《用户端前端设计（问答页）》）—— 本文件由「问答页单页设计稿」整体升级为**覆盖全前端（用户端 + 管理端）**的界面设计基线。
**设计基准**：项目根目录 `demo.html`（单文件高保真原型，8 视图 + 完整 design token）。
**关联文档**：[v2产品规划.md](./v2产品规划.md)、[详细设计_v2.md](./详细设计_v2.md)、[rebuild-frontend-v2/spec.md](../.trae/specs/rebuild-frontend-v2/spec.md)、[rebuild-frontend-v2/tasks.md](../.trae/specs/rebuild-frontend-v2/tasks.md)
**性质**：实现前需评审通过；**本变更不修改后端与业务逻辑**，冲突项见 §9。

---

## 1. 版本与范围

- **定位变更**：v1 前端为「管理端优先」形态（Element Plus 侧边栏壳 + 独立深色玻璃问答页），与 v2 定稿定位（**私有化单实例团队知识库 + RAG 问答**）不匹配。本设计**废弃旧前端方案**，以 `demo.html` 为唯一视觉与信息架构基准重建。
- **覆盖范围**：
  - 用户端：首页 `/`、问答 `/qa`、知识库 `/kb`、文档详情 `/kb/doc/:id`、登录 `/login`、Setup 向导 `/setup`、个人中心 `/me`、写文档 `/editor`。
  - 管理端：`/admin` 及子路由（概览 / 文档管理 / 数据导入 / 成员管理 / 问答统计 / 知识盲区 / 待复审）。
- **交付节奏**：**先迁移并测试已实现功能**（问答、登录、管理端文档列表/导入/active 切换/删除/chunks），确认迁移成功后再进入 v2 新功能开发；迁移期间**保持前后端接口契约不变**（见 §8）。依赖未就绪后端的页面一律做**外壳（UI 骨架 + 空态）**，禁止 mock 伪造业务数据（见 §10）。

## 2. 设计原则与组件库策略

**技术栈沿用**：Vue 3 + Vite + Element Plus + Pinia + Vue Router + axios + TypeScript（依赖见 `frontend/package.json`）。

**原则**

1. **单一视觉语言**：全站（含管理端）采用 demo 的暖橘 token 体系统一呈现，不再区分「用户端深色玻璃 / 管理端青色工具风」。
2. **保留 Element Plus，不做替换**：EP 承担表单/表格/弹窗/消息等**交互型组件**，通过全局 CSS 变量覆盖使其主色、圆角、字体贴合 demo（见 §3.2）；视觉型组件（导航、卡片、Hero 等）用自定义组件按 demo 结构还原。
3. **契约不变优先**：迁移阶段只消费现有接口，不改请求/响应结构、不引入新的业务判断。
4. **减量优先**：删除被取代的旧布局/旧视觉/旧路由，合并重复组件与样式，避免双份实现。

**EP 组件 vs 自定义组件分工**

| 类别 | 采用 Element Plus | 采用自定义（demo 还原） |
| --- | --- | --- |
| 按钮 / 下拉 / 复选 / 单选 / 输入 | 管理端表单区、登录页（`el-button` / `el-select` / `el-switch` / `el-input`） | 用户端首页/问答页按钮、chip、导航（demo `.btn` / `.chip`） |
| 数据展示 | 管理端 `el-table` + `el-pagination` | 首页 Stats、产品线卡、知识库文档卡、管理端统计卡（可选 `el-table`） |
| 反馈 | `ElMessage` / `ElMessageBox` / `el-drawer` / `el-tag` | 问答页骨架屏、兜底卡、引用脉冲高亮 |
| 布局 | — | NavBar / UserMenu / AppFooter / PageHead / AdminLayout（`.nav` `.footer` `.admin`） |
| 图标 | `@element-plus/icons-vue`（管理端） | demo 内联 SVG（用户端导航/卡片/图标） |
| 兜底 | — | 空态占位组件（§10） |

## 4. 信息架构与路由表

### 4.1 导航结构

- **主导航**（NavBar 中央）仅三项：**首页 / 问答 / 知识库**，当前项以 `--brand-500` 圆点高亮（demo `.nav__link--active::after`）。
- **账户类入口**（右上头像菜单 UserMenu）：**个人中心 / 写文档 / 我的收藏 / 管理后台 / 退出登录**。管理后台项带 `admin` 徽标，且**不出现在主导航**。
- **未登录态**：NavBar 右侧展示「登录」按钮；demo 的「免费开始」为 `/setup` 入口，因 Setup 后端未就绪，本轮保持现状或降级（见 §9 C1/C2）。
- **页面 Footer**：全站统一 `AppFooter`。

## 8. 接口契约基线

迁移期间前端消费的**现有后端接口**，**不得更改请求/响应结构**（照抄 spec.md）：

| 接口 | 方法/路径 | 契约要点 |
| --- | --- | --- |
| 注册 | `POST /api/auth/register` | `{username,password}` → `AuthResponse{token,user{id,username,role}}` |
| 登录 | `POST /api/auth/login` | 同上 |
| 当前用户 | `GET /api/auth/me` | → `UserDto` |
| 版本列表 | `GET /api/qa/versions` | → `string[]`（公开） |
| 问答 | `POST /api/qa/ask` | `{question,version?,topK?}` → `QaResult{found,answer,sources[]}` |
| 检索 | `GET /api/qa/search` | `?q&version&topK` → `List<Map>` |
| 文档列表 | `GET /api/admin/documents` | `?source&version&active&keyword&page&size` → 全量数组或分页 `PageResult` |
| 导入 | `POST /api/admin/documents/import` | `ImportRequest` → `ImportResult{imported,skipped,docId}` |
| active 切换 | `PATCH /api/admin/documents/{id}/active` | `{active}` → `DocumentDto` |
| 删除 | `DELETE /api/admin/documents/{id}` | → `null` |
| chunk 列表 | `GET /api/admin/documents/{id}/chunks` | → `Chunk[]` |

## 9. 待确认（C1~C8 —— 只列出，不擅自修改）

> 以下为 v1 现有业务逻辑/接口与 v2 目标的冲突点。**本变更不实施**，本轮前端对相关页面一律**保持现状或空态占位**，待用户逐条裁决后再单独开变更处理。

| # | 冲突点 | v1 现状 | v2 目标 | 影响面 |
| --- | --- | --- | --- | --- |
| C1 | 开放注册 | `POST /api/auth/register` permitAll，任何人可注册成成员 | setup 向导创建首个 admin，成员由 admin 邀请/管理 | SecurityConfig、AuthController、登录页注册 tab、路由 |
| C2 | 问答免登录 | `/qa` public + `/api/qa/**` permitAll | 默认全站登录；`allow_anonymous` 由 setup 决定是否放行 /qa、/kb 只读 | SecurityConfig、路由守卫、导航 |
| C3 | 无角色区分 | 任意登录用户即可访问 `/api/admin/*` | admin/member 两角色，管理端仅 admin | SecurityConfig、管理端路由守卫 |
| C4 | 文档可见性缺失 | 无 `visibility`/`owner_id`，检索无可见性过滤 | private/team 两级可见，检索强制过滤 | 后端 schema/检索、知识库与详情页展示 |
