**版本**：v2.2（2026-10-20 方向定稿；2026-10-26 补落地进度）

## 1. 产品定位（定稿）

> **SpringKB = 小型技术团队的私有化知识库 + RAG 问答**
>
> 一个轻量、可本地部署的团队知识库：官方技术文档预置开箱即用，团队成员沉淀自己的经验文档，RAG 引擎让所有人通过自然语言问答秒级获取知识。

| 维度 | 定稿 |
| --- | --- |
| 目标用户 | 5~50 人技术团队 |
| 部署形态 | **私有化部署**：docker compose 一键起，单实例单团队，跑在团队自己的机器/NAS/云主机 |
| 使用形态 | 浏览器访问（B/S），首次启动向导初始化团队，后期支持 PWA 安装到桌面 |
| 内容来源 | ① 官方文档预置（爬虫种子内容，authority=official）② 团队成员 UGC（自己写/上传，authority=ugc） |
| 核心能力 | RAG 问答（引用可溯源）＞ 知识浏览 ＞ UGC 沉淀 ＞ 运营统计 |
| 安全模型 | **隔离在部署边界**（同 GitLab/Gitea）：不做多租户，实例内 admin/member 两角色 + 文档 private/team 两级可见 |

### 1.1 定位演进记录（为什么是这个形态）

| 轮次 | 方向 | 结论 |
| --- | --- | --- |
| 初版想法 | 像 CSDN 一样的知识社区 + RAG | 社交功能（关注/评论）在小团队空转，砍掉或延后 |
| 中间方案 | 多租户 SaaS 平台 | 企业不愿把机密放别人服务器；多租户在私有化下是伪需求 |
| **定稿** | **私有化单实例，隔离在部署边界** | 物理隔离强于行级逻辑隔离，架构更简单、安全故事更好讲 |

### 1.2 明确不做清单

| 不做 | 理由 |
| --- | --- |
| 多租户 / workspace 隔离 | 私有化部署下由部署边界天然隔离，tenant_id 是死重 |
| 平台公共区 / 跨公司互动 | 低价值高合规风险；官方文档就是各实例的预置内容 |
| 关注作者、评论系统 | 小团队社交空转；仅保留点赞+收藏（一键反馈，反哺检索权重） |
| 在线协同编辑 / 版本历史 | 这是飞书/Confluence 的事；我们是"写作轻、检索重" |
| 对外分享链接 | 私有化产品的安全红线 |
| 移动端 / IM 嵌入 | 超出范围 |
| API Key 开放平台 | 私有部署内部使用，JWT 够用（如有个自动化需求再补） |

## 2. v1 用户视角痛点（本轮触发，仍然有效）

| # | 痛点 | 影响 | v2 对应 |
| --- | --- | --- | --- |
| P1 | 不知道知识库里有什么（混在一起） | 无法探索、不敢提问 | V2.0 知识库导航页（左体系树 + 右文档卡） |
| P2 | 不知道支不支持中文匹配 | 中文问法普遍兜底（坑#22） | V2.1 双语验证 + 中文检索 |
| P3 | 引用卡片是 chunk 粒度、无法跳原文 | 来源冗余、无法深度溯源 | V2.0 来源聚合 + 原文跳转 |
| P4 | 数据量少（235 篇） | 覆盖面窄 | V2.1 爬虫扩展 → 1500+ |
| P5 | 引用与答案割裂 | 不知道哪句对哪个来源 | V2.0 角标精准联动 |
| P6（新增） | 团队自己的经验无处沉淀 | 知识库只有"别人的"文档 | V2.2 UGC（写文档/上传，private/team） |
| P7（新增） | 文档会过期、不敢信 | 知识库慢性病 | V2.3 新鲜度机制（过期降权 + 复审提醒） |

## 3. 产品形态与信息架构

> 信息架构已在 `demo.html` 原型中完整落地（8 视图 + 头像菜单承载账户类入口，主导航仅 首页/问答/知识库 三项，管理后台不进主导航）。各阶段前端实现时从原型迁移组件与样式 token。

```
首次启动 → /setup 向导（创建团队名 + admin 账号 + 是否预置官方文档包）

登录后：
├── 首页 /            品牌 + 搜索入口 + 统计 + 产品线卡片（demo.html 原型已实现）
├── 问答 /qa          核心：自然语言提问 → 答案 + 文档级来源卡 + 原文跳转
├── 知识库 /kb        左侧体系树（产品线 ▸ 版本 ▸ 来源）+ 右侧文档卡
├── 文档详情 /kb/doc/:id   Markdown 原文 + 「基于本文提问」+ 关联推荐 + 点赞/收藏
├── 个人中心 /me      头像 / 改密码 / 我的文档 / 我的收藏 / 我的贡献统计
├── 写文档 /editor    Markdown 编辑器 + 可见性选择（private/team）+ 发布（密钥扫描）
└── 管理后台 /admin   成员管理 / 文档管理 / 统计看板（命中率/盲区/贡献榜/待复审）
```

**访问控制默认**：团队实例默认全站登录后可访问；`app_setting.allow_anonymous` 可开启"问答+知识库免登录"（v1 行为），由 setup 向导决定。

## 4. 权威性加权（接入 UGC 后的三档权重）

| 档位 | 来源 | boost | 说明 |
| --- | --- | --- | --- |
| 1 | 官方文档（爬虫预置） | 1.0 | authority=official，不变 |
| 2 | 团队 UGC | 0.9 | 本团队自己沉淀的经验，可信度仅次于官方 |
| 3 | 社区内容（SO 等） | 0.8 | authority=community，不变 |

**新鲜度因子（V2.3 叠加）**：`final_score = score × boost × freshness`

- `last_verified_at` 距今 ≤ 180 天 → freshness = 1.0
- 180~365 天 → 0.9（卡片标"待复审"灰色徽标）
- \> 365 天 → 0.8（检索降权，倒逼 owner 复审）

**点赞反哺（V2.4 叠加）**：文档点赞数 ≥ 10 → 额外 ×1.05（封顶），让团队用脚投票的结果进入排序。

## 6. 关键场景（验收用叙事）

1. **新人入职**：打开内网 SpringKB → 首页看到知识库覆盖 Spring Boot/Vue 共 1500+ 篇 → 直接问"我们项目的 CDS 怎么配"→ 命中团队前辈写的 UGC 文档（权威加权让它排在社区内容前面）→ 点开来源卡看原文 → 顺手点赞
2. **问题解决后沉淀**：开发踩坑 → 知识库没搜到 → 自己解决 → /editor 写 Markdown 或上传 `.md`（自定义技术分类/版本 + 可见性 team）→ 发布 → 同事检索命中（密钥扫描为后续计划项）
3. **文档腐化治理**：admin 看板显示 12 篇文档超 180 天未复审 → owner 收到提醒 → 确认仍有效点"已复审"→ 权重恢复
4. **盲区补知识**：看板显示"如何配置 XX"被问了 15 次全部兜底 → admin 安排人写一篇 → 下次能答
5. **隐私保护**：成员把含内部信息的文档设为 private → 其他成员在知识库列表/详情看不到，问答也不会引用；自己提问同样不引用（避免答案泄露给他人）；改回 team 后立即可检索

## 7. 已知约束与风险

1. **Embedding 维度不可变**：换模型必须全量重建向量库（V2.1 先验证再决策）
2. **UGC 冷启动**：团队没人写文档则 UGC 闭环空转 → 贡献统计 + 导入器降低录入成本是关键，不是靠社交激励
3. **密钥扫描误报**：正则+熵检测有误报率，采用"提醒不拦截"策略，由作者确认
4. **爬虫版权**：官方文档/SO（CC BY-SA 署名）可爬，中文站需评估；UGC 天然规避
5. **LLM 引用标记稳定性**：先做 `[n]` 文档级，`[n.m]` chunk 级验证稳定再开
6. **匿名开关与私有性冲突**：`allow_anonymous=true` 时 private 文档绝不能被检索到——检索过滤必须在 service 层强制，不依赖前端传参
