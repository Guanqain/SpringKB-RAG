# 检索基线测评 · 实施计划

> 目标：为 SpringKB-RAG 的**检索阶段**产出一份可信的、可复现的基线数据（不含生成）。
> 载体：后端 Java 评测 Runner（`--baseline`）+ 混合 ground truth（合成为主 + 精选为辅）。
> 数据：真实语料 1445 篇 / 3263 chunks + 真实百炼 Embedding（`text-embedding-v4`）。

## 1. 现状分析（已探查确认）

- 检索三能力已实现，代码位于 `com.guangqian.springkb.rag` 包：
  - `RagSearchService.search(query, version, topK)` → 返回重排后 chunk 行 `{id, score, content, source(=authority), version, title, doc_id, active}`（[文件](file:///c:/Users/19937/IdeaProjects/springKB/src/main/java/com/guangqian/springkb/rag/RagSearchService.java)）。
  - `RagSearchService.searchDocuments(query, version, topK)` → 返回初检原始 `Document`（含 metadata），供兜底/重排复用。
  - `Reranker.rerank(...)` / `RagSearchService.rerankAndTop(candidates, topK)` → `score' = score + (authority=='official' ? boost : 0)`，boost 默认 0.15。
  - `QaService` 兜底阈值 `app.rag.similarity-threshold`，**application.yml 实际配置为 0.5**（代码构造器缺省 0.65 仅兜底）。
- **无任何已有评测集**：现有 6 条验证用例（createApp / graceful shutdown / password storage / vite pre-bundling / sourdough 兜底 / reactive array 边界），仅覆盖了官方文档维度的少量场景。
- 语料元数据表 `kb_document`（schema.sql）可查询列：`id, product, title, origin, authority, version, doc_key, doc_type, language, section, active, chunk_count`。`kb_chunk` 可查询 `id, doc_id, ordinal, heading_path, content_markdown, content_text, token_count`。
- 运行环境现状：
  - 数据卷 `springkb_springkb-pgdata` 存在（1445 篇文档仍在，容器已停止，需 `docker compose up -d postgres` 拉起）。
  - `DASHSCOPE_API_KEY`、`DEEPSEEK_API_KEY` 均已设置（评测只用到 DASHSCOPE，Embedding）。
  - 既有 Runner 模式：`ImportRunner` / `CrawlerRunner` 均实现 `ApplicationRunner`、注入 `tools.jackson.databind.json.JsonMapper`、用 `args.getOptionValues("...")` 判断是否激活、无参则跳过、数据落盘 `data/`。**评测 Runner 完全沿用此模式**。

## 2. 方案概览

### 2.1 数据流

```
docker compose up -d postgres        # 拉起含 1445 篇的 pgvector
mvnw spring-boot:run                 # dev profile（真实 Embedding）
mvnw spring-boot:run -Dspring-boot.run.arguments="--baseline"   # 跑评测
  └─ BaselineRunner:
       1) 从 kb_document/kb_chunk 读活跃语料，固定种子分层抽样
       2) 生成「合成自检索」查询 + 加载「精选真实」查询（resources/eval/queries.json）
       3) 两组检索：开放版本(version=null) + 锁定版本(version=doc.version)
       4) BaselineEvaluator 计算四维指标
       5) 结果 JSON 落盘 data/baseline/result-<ts>.json + 写 docs/检索基线测评报告.md
```

### 2.2 Ground truth 构建（混合，已定）

| 子集 | 构造方式 | 标准答案 | 用途 |
| --- | --- | --- | --- |
| 合成自检索（主体，~120 条） | 从活跃语料按 `product × authority × version` 分层抽样，查询 = `title + " " + 首块 heading_path 末段`（叠加首块前若干词增强特异性，标题即可回退纯 title） | 该文档 `doc_id`（doc 级） | IR 指标、版本过滤、兜底、重排 |
| 精选真实问句（~25 条） | 手工构造，覆盖 10 源（Spring Boot/Security/Framework/AI/Data JPA + Vue/Router/Pinia/Vite + Stack Overflow）+ 2~3 条无关问法（负例） | 期望命中的 `title`（运行时精确匹配解析为 doc_ids） | 贴近用户读值、兜底负例 |
| 负例 | 无关查询（如烘焙/烹饪） | 空集合 | 兜底行为 |

- 合成查询锁定版本时，会**额外**跑一轮 `version = doc.version` 的检索，用于「版本过滤正确性」。
- 合成抽样固定 `seed = 42`、`sample = 120`（可 `--baseline-sample=N` 覆盖），保证可复现。

### 2.3 指标定义（四维，已定）

先对检索结果按 `doc_id` 去重（保留首次出现），得到有序 doc 列表；`rel(q)` = 该查询相关 doc_id 集合。

- **标准 IR**（TopK ∈ {5, 10}）：
  - `Hit@k` = rel ∩ top-k 非空 ? 1 : 0（均值）
  - `Recall@k` = |rel ∩ top-k| / |rel|
  - `Precision@k` = |rel ∩ top-k| / k
  - `MRR@k` = mean( 1 / rank(first relevant) )，rank>k 记 0
  - `nDCG@k` = mean( 1 / log2(rank+1) )，rank>k 记 0（单一相关文档下的二元相关简化）
- **版本过滤正确性**（锁定版本子集）：
  - `targetHit` = 目标 doc 进 top-k
  - `leakRate` = 返回结果中出现 `version != doc.version` 的查询占比（应 = 0）
  - `correctness` = targetHit 且无泄漏 的查询占比
- **兜底行为**：对「有能力命中」的查询集，统计 `topScore < app.rag.similarity-threshold(0.5)` 的占比 = 兜底率；并输出 topScore 的 min / median / max 分布。
- **权威重排效果**：对含 official 相关文档的查询，用 `searchDocuments(30)` 取初检序 + `rerankAndTop(10)` 取重排序，统计 official 目标 doc 的「名次提升占比」与「平均名次提升」，并确认无 community 被误剔。

## 3. 变更清单

### 3.1 新增：评测包 `src/main/java/com/guangqian/springkb/eval/`

**`eval/BaselineRunner.java`**（ApplicationRunner）
- `getOptionValues("baseline")` 非空才执行，无参跳过（同 ImportRunner/CrawlerRunner）。
- 注入 `RagSearchService`、`JdbcTemplate`、`JsonMapper`。
- 流程：读活跃语料（`kb_document` JOIN `kb_chunk` 取首块 heading）→ 分层抽样 → 合成查询 + 加载精选查询 → 双模式检索 → 调 `BaselineEvaluator` → 落盘 JSON + 报告。
- 支持参数：`--baseline`（启用）、`--baseline-sample=N`（默认 120）、`--baseline-topk=10`（默认 10，同时算 5/10 两档）。
- 报告内嵌 methodology 与 caveat（阈值/boost 来源、合成自检索高估说明）。

**`eval/BaselineEvaluator.java`**（纯函数，无 Spring 依赖）
- 提供 `hitAtK / recallAtK / precisionAtK / mrr / ndcg / versionLeakRate / fallbackRate / rerankShift` 等静态/纯方法，便于单测。
- 输入输出用 record（`QueryRun`、`MetricsSummary`）。

**`eval/CuratedQuery.java`**（record）
- 字段：`id, query, version(nullable), relevantTitles(List<String>), category`。

### 3.2 新增：精选查询集 `src/main/resources/eval/queries.json`（版本控制的金标集）
- 结构见 `CuratedQuery`，含约 25 条：各源 2~3 条真实问法 + 2~3 条负例；`relevantTitles` 用文档真实标题（从 `data/raw/*.json` 与 readme 验证用例反查，运行时解析为 doc_id）。

### 3.3 新增：单测 `src/test/java/com/guangqian/springkb/eval/BaselineEvaluatorTest.java`（纯 JVM，不碰 DB）
- 固定构造的「查询→检索序」样例，断言 `hitAtK / mrr / ndcg / recall / precision / versionLeak / rerankShift` 计算结果正确，锁住指标口径（呼应「可信」要求）。

### 3.4 产出（运行时生成，非手写）
- `data/baseline/result-<ts>.json`：每条查询的完整明细（query/version/targetDoc/retrieved[doc_id+score]/topScore/命中rank/是否泄漏/重排前后 rank）。
- `docs/检索基线测评报告.md`：四维指标汇总表 + 分源/分版本/分权威性拆解 + 方法论与已知偏差。

- 新增 `docs/devlog/2026-10-25.md`：记录问题/方案/指标结论/经验教训（如合成自检索高估、外网可达性）。

## 4. 假设与决策

| 项 | 决策 |
| --- | --- |
| 兜底阈值 | 取 `application.yml` 实际值 `app.rag.similarity-threshold = 0.5`（非代码默认 0.65） |
| boost | `app.rag.boost = 0.15`（运行时通过注入 `Reranker.getBoost()` 读取，报告中回显） |
| 相关性粒度 | 合成=doc 级单相关；精选=title 级（精确匹配解析为 doc_id，解析失败则该条标记 skipped 不计入分母） |
| 合成抽样 | 固定 seed 42，`product × authority × version` 分层，缺量时整体按比例补齐 |
| 合成查询文本 | `title + heading 末段 + 首块前 ~20 词`，无首块则退化为 `title` |
| 指标截止 | TopK ∈ {5, 10}；MRR/nDCG 用 10 |
| Embedding | 真实百炼 `text-embedding-v4`（1024 维），不 mock |

## 5. 验证步骤（执行阶段）

1. `docker compose up -d postgres` 并确认 `ragdb` 可连、`kb_document` 计数 ≈ 1445。
2. `./mvnw -q compile` 通过（新增 eval 包无法编译则回看 Java 17 / Jackson 3 API）。
3. `./mvnw -q test -Dtest=BaselineEvaluatorTest` 通过（指标口径锁定）。
4. `./mvnw spring-boot:run -Dspring-boot.run.arguments="--baseline"` 跑完，检查：
   - `data/baseline/result-*.json` 生成、查询数与抽样数一致、无异常堆栈；
   - `docs/检索基线测评报告.md` 各表数字非空且四维齐全；
   - 抽查 3~5 条查询的检索结果与 `/api/qa/search` 手工比对一致（可信性抽检）。
5. 核对版本过滤 `leakRate == 0`、兜底率处于合理区间、重排提升方向符合 boost 语义。

## 6. 风险与前置

- **外网可达性**：真实 Embedding 需 `dashscope.aliyuncs.com` 可达（参考 agent.md 坑 #32 的 deepseek 不可达先例）。若不可达，评测无法跑真实基线（不可 mock 替代；需换网络或重建密钥后重试）。
- **数据卷一致性**：务必用 `docker compose up -d postgres` 复用 `springkb_springkb-pgdata`，避免误建空库导致「0 文档」。
- **采样代表性**：社区（community）样本仅 251 篇、且为 SO 问答，合成自检索对其标题的特异性较低，属预期偏差，报告中显式说明。
